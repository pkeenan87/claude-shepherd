# AGENTS.md

Being migrated from a Pi extension to a Claude Code plugin; see docs/PLAN.md.

shepherd is a Pi extension for `/plan` → `/build` → `/review`: a model per ticket difficulty, a per-ticket review, and cost tracking. User docs (pi-chef's, in `docs/pi-chef/`, to be rewritten): (`commands.md`, `configuration.md`, `providers.md`, `install.md`, `COMPATIBILITY.md`). This file is for agents and people changing the repo.

## Commands

```bash
npm test            # vitest, no network
npm run typecheck   # src and tests
npm run build       # tsc to build/ (gitignored; the chef-config CLI and herdr:install run from it)
npm run bundle      # esbuild: src/cli/shepherd.ts to dist/shepherd.mjs and src/ticket-mode.ts to dist/ticket-mode.mjs (the Pi worker: Pi's own @earendil-works/* and typebox external, yaml inlined); both committed and kept fresh (CI runs git diff --exit-code dist/)
```

Run tests with `TMPDIR=~/.cache/pi-chef-rework-tmp npm test` if the default temp dir is unsuitable. Tests and typecheck must be green before a change is done. There is no lint script. Keep `docs/` in step with `src/config.ts` (`KNOWN_KEYS`, defaults) and `templates/shepherd.yaml`.

## Layout

Entry and shared
- `src/index.ts`: package exports.
- `src/extension.ts`: Pi entry point. Registers commands, session hooks (`session_start`, `message_end` ledgering, `tool_call` blocks), the `local` provider and tools; keeps one `Workflow` per cwd; keeps a thin `buildHost` that adds Pi's registry check and the local-context warning to the shared driver. `bindHerdrClient` is the test seam for the herdr client. Pi-only until the extension is removed (phase 5).
- `src/commands.ts`: the command table (name, description, completions; `drive` for `/build`).
- `src/config.ts`: YAML loading, validation, whole-section layering (`layerConfigs`), pricing lookup.
- `src/agents.ts`: built-in external agents, `parseTicketModel`, `agentCommand`.
- `src/domain.ts`: shared types (task state, phases, tickets, cost records) and `WorkflowError`.
- `src/redact.ts`: secret detection and redaction.
- `src/sandbox.ts`: command walker behind the deny rules (`assertCommandSafe`, `isDeniedCommand`) and the `/build` bash block (`buildBashBlock`).
- `src/usage-message.ts`: turns a Pi assistant message into a ledger entry.
- `src/ticket-mode.ts`: the extension a Pi ticket child loads with `-e` (turn budget, bash rules, `local` provider, status file); never listed in `package.json`.

Orchestrator (`src/orchestrator/`)
- `service.ts`: the `Workflow` facade over a shared `WorkflowContext` (`context.ts`).
- `machine.ts`: phase transitions. `types.ts`: shared callback types. `format.ts`: progress and report formatting.
- `planning.ts`: new tasks, `/plan`. `interview.ts`: the interview and spec. `prompts.ts`: planning prompts. `plan.ts`: `plan.md`. `present-plan.ts`: posting a saved plan and the approval picker. `classification.ts`: the planner's rating.
- `tickets.ts`, `ticket-plan.ts`: ticket validation, context sizing, ticket files.
- `tasks.ts`: names, listing, active task, closing. `plans.ts`: `/plans`.
- `build.ts`: `/build` (`startBuild`, `nextChunk`, `finishChunk`, `runBuild`), pure over a `BuildDriver`. `routing.ts`: model per difficulty and escalation. `turn-budget.ts`: ticket turn limit. `ticket-review.ts`: the per-ticket review gate.
- `review.ts`: `/review`. `review-report.ts`: its report and numbered findings. `agent-review.ts`: the `/review` model pass run in a herdr sub-agent, by an external agent or a Pi child (`runAgentReview`; one turn, no chunking: the reviewer runs `git diff <merge-base>` itself, so `review.maxChunks`/`maxDiffChars` apply only to the chat-call pass of the Pi extension). `tab-program.ts`: the Pi-child and agent programs (argv, ledgering, reply) shared by the fix and the ticket review. `ticket-review-tab.ts`: the per-ticket review run in a herdr sub-agent. `review-fix.ts`: "Fix all in a tab", the findings fixed by `models.medium` in a herdr tab, ledgered as "review fix".
- `budget.ts`: usage recording and budget checks. `reports.ts`: `/cost`. `exec.ts`: running checks.

Runners, providers, review, storage
- `src/cli/build-host.ts`: the Pi-free `/build` driver (`createBuildDriver`: herdr preflight, optional model preflight, `pi`-on-PATH check, `runTicket`) and `ticketModePath()` (walks up from the module: `dist/shepherd.mjs`, `build/cli/`, `src/cli/`; prefers `<plugin>/dist/ticket-mode.mjs`, which a plugin install can load without node_modules, else `src/ticket-mode.ts`). `src/cli/build.ts`: `shepherd build [--once] [--json]` over `runBuild` (progress to stdout; with `--json` stdout is one `{ok, code?, text, data}` document whose `text` holds the progress lines; `data` for `--once` is `{ticket?, outcome: committed|stopped|done, done, stopped?, next?, report?}`; SIGINT/SIGTERM kill the open tabs, release the claim and exit 130). Test seams in `CliOptions`: `herdr`, `runner`, `herdrTimings`, `piAvailable`, `ticketModePath`, `exit`. Skill: `skills/build`.
- `src/cli/review.ts`: `shepherd review [--with <model>] [--json]` and `shepherd fix --tab|--list [--json]`, adapters over `Workflow.review`, `fixInTab`, `fixList` (`orchestrator/review-latest.ts`: the latest saved report, `fixModel`, the fix on it). No `report`/`review`/`startTurn` is bound, so a review's result text is the whole numbered report. `--json` gives `{ok, code?, text, data}`; a review's `data` is `{report (absolute .md path, null when nothing was reviewed), findings: [{n, title, file, line (always null: findings record no line), risk (the table label)}], passed, fixTab (the `models.medium` that can fix in a tab here, else null)}`; a blocking review is `ok: false, REVIEW_BLOCKING`, exit 1. `fix --list` data is `{report, findings}` and its text the "fix in this chat" message. Skill: `skills/review`.
- `src/runner/ticket.ts`: dispatch (Pi model or agent) and the herdr requirement. `tab.ts`: the one open/send/wait/close loop (tab names, `send --wait`, blocked handling). `pi-ticket.ts` and `agent-ticket.ts`: how each starts its program and what it collects after a turn (a Pi child's session files; an agent's usage log, branch check and summary file). `host.ts`: session dirs, ledgering, git moves. `agent-usage.ts`: metering from agent logs.
- `src/herdr/client.ts`: typed wrapper over `hc` (self, run, send, waitIdle, read, kill). `session-file.ts`: reads a Pi child's session files for usage.
- `src/providers/`: `runtime.ts` (registers `local`), `known-models.ts` (presets), `local-context.ts` (served context probe), `clients.ts` and `pi-chat.ts` (model calls through Pi's registry), `usable.ts` (`registryProblem`).
- `src/review/`: `review.ts` (checks and static scan), `model-review.ts` (the `/review` model pass), `risk.ts` (scoring shared by all reviews), `scored-json.ts` (reading, deduping and filtering scored findings, shared by the model pass, agent review and ticket review).
- `src/cost/ledger.ts`: summaries and budget status. `src/storage/store.ts`: task state, event log, ledger, ticket log, locks. `src/git/workspace.ts`: git over `execFile`.
- `src/tools/`: `web-search.ts`, `web-fetch.ts` (with `html-to-markdown.ts`), `readonly-bash.ts` (the `/plan` allowlist), and the plan tools (`index.ts`, `plan-flow.ts`, `plan-questions.ts`, `plan-review.ts`).
- `src/cli/shepherd.ts` (the `shepherd` CLI, run through `bin/shepherd`; bundled to `dist/shepherd.mjs`): `cost [--json]`, `status`, and `hook stop|prompt|pretool` (the plugin's hooks, `hooks/hooks.json`). `src/cli/bash-guard.ts`: the command splitter behind the PreToolUse guard. `src/shepherd-home.ts`: `$SHEPHERD_HOME` (default `~/.claude/shepherd`): `repos.json`, `sessions/`, `warned.json`.
- `src/cli/plan.ts`: `shepherd plan start|spec|tickets|show|revise|approve`, `plans` and `task list|use|close`, thin adapters over the `Workflow` planning methods (all take `--json`: `{ok, code?, text, data?}`; file args are a path or `-` for stdin; exit 1 on a failed result). `startPlan`/`requestPlanChanges` take `headless` so no Pi turn is needed. Opus drafts and the CLI validates; there is no `plan answers` (the interview lives in `skills/plan`, its answers go into the spec's `decisions`). `pretool` returns `ask` for `shepherd plan approve` (reason names task, tickets, models), so the approval is the user's whatever a skill's `allowed-tools` say. Skills: `skills/plan`, `skills/plans`.
- Plugin: `.claude-plugin/plugin.json` and `marketplace.json` (the plugin name must not start with `claude-`), `hooks/hooks.json`, `skills/<name>/SKILL.md`. Check with `claude plugin validate .`.
- `src/cli/chef-config.ts` (with `bin/chef-config.mjs`): JSON CLI for the herdr panel. `src/cli/herdr-layout.ts`: docks the panel in a layout.

Elsewhere: `scripts/herdr-install.mjs`, `herdr/chef-config/` (the panel mod), `templates/shepherd.yaml` (user config template), `templates/project-config.yaml` (project sample), `skills/chef-workflow/`, `tests/` (mocks only; `helpers.ts`, `herdr-fake.ts`).

## Rules

- **Cloud providers use whatever login or key Pi holds.** shepherd checks `modelRegistry.find` and `hasConfiguredAuth` (`registryProblem`) and never reads provider key variables. Prices come from `pricing` rows; a model with no row is an unknown cost, never $0 (except `local`). Do not name a config field so it ends in a secret word (`apiKey`, `token`): `containsSecret` rejects it.
- **No secrets in config or state.** `assertNoSecrets` enforces it. The local server's key is a variable name (`local.apiKeyEnv`) that Pi resolves. Never log secrets or write them to state, the ledger or prompts.
- **Policy is deterministic; models only fill validated schemas.** Plan approval is always required. Nothing pushes, opens a PR or merges.
- **Layering is one rule:** a project section replaces the user's whole section (`layerConfigs`). `local`, `agents`, `pricing` and `workspaceDir` are user-only; a project value is ignored with a warning. Remote `local.baseUrl` must be https; only loopback may be http. An agent's `run` comes from the user file only.
- **Unknown config keys are ignored with one warning** (`KNOWN_KEYS` in `config.ts`). Any invalid value, secret or bad YAML rejects the whole file (`ConfigFileError`); it is surfaced at session start, never swallowed, and never crashes the session.
- **Routing:** a ticket starts on `models.<difficulty>` (`modelFor`), climbs low, medium, high on failure (a rung naming the same model is skipped) and stops above `high`. `routing.maxEscalations` counts rungs climbed to the next rung with another model. Resume keeps the rung (`TicketRun.tier`); review rounds are counted per rung.
- **Every `/build` ticket runs in its own herdr sub-agent (or tab with `build.visibleTabs`), in the current checkout.** Without herdr, `runBuild` returns `NEEDS_HERDR` before `startBuild`, so no branch is made. The driver never throws; `runTicket` returns `{ stopped }`. A fresh build gets `<branchPrefix>/<name>` from the default branch; `startBuild` claims the task by pid.
- **Sub-agents are paneless by default.** `hc run` from inside the Claude Code terminal records it as the child's `parent`; ticket, review and fix runs pass no `herdr.space`/`herdr.tab` label (`openTab` adds them only when given a `space`, which `herdrSpace(client, visible)` yields only with `build.visibleTabs: true`). The preflight needs only `HC_TERMINAL_ID` and a working `hc` (`client.self()` reads the space label when there is one). Each run keeps a `shepherd.*` label.
- **The per-ticket review runs in a tab outside Pi.** `reviewTicket` uses Pi's chat client when one is bound (the extension), else a herdr sub-agent (`askInTab`): `models.review` as an agent or a Pi child, which reads the checkout (`git diff HEAD`) and writes `{summary, findings}` JSON to `reports/ticket-review-<id>-<time>.json`. Same parser, risk filter and `TICKET_FAIL_RISK` gate. Rows are `ticket review · ticket <id>`, tier `review`. HEAD and branch are guarded (a commit is soft-reset, a branch change is unavailable) and the diff is fingerprinted: a review that edited the tree is unavailable, so the ticket is committed with a warning. Skipped when `review.tickets` is false or no herdr client is bound. A Pi review's session dir is `sessions/review-<ticket>-<time>`, never `<ticket>-<n>`.
- **The /review model pass outside Pi always runs in a herdr sub-agent** (`modelPass`: an agent, or a Pi model when no `ctx.chat` is bound; the extension's bound chat keeps the one-shot call until phase 5). Rows are `model review`, tier `review`, phase REVIEWING, under the task (else `session`); a Pi child's rows take that task and phase through `piProgram`/`ledgerChildSession`. Without herdr the setup, checks and static scan still run and the model stage reads "the model pass needs herdr". `shepherd fix --tab` fixes the latest report's findings on `models.medium` in a sub-agent (`review fix`, never commits); a Pi `models.medium` is checked only for `pi` on PATH (`ctx.piAvailable`) unless a registry is bound.
- **Outside Pi there is no registry.** Routing (`routeFor`) blocks a Pi model when `ctx.piAvailable` says `pi` is not on PATH; `shepherd build` fails `NEEDS_PI` first when the next ticket starts on one. Whether Pi knows the model or has a login is the Pi child's to say.
- **`shepherd build --once` builds one ticket** (`runBuild(..., {once: true})`: exits after the first commit; stops and escalation are unchanged) and holds the build claim only while it runs, so the pretool git guard is off between runs.
- **A Pi ticket child is a `pi` of its own** (`pi -ne -e ticket-mode.ts --model … --session-dir …`, environment through an `env` wrapper); its session files are ledgered. **An agent ticket is a CLI in a tab and shepherd owns the commit:** a commit the agent makes anyway is undone with `git reset --soft`, but only while the checkout is still on the build branch (else the ticket stops and HEAD is left alone). The agent writes its summary and criteria checklist to a file under the task's `sessions/`; that file, not the screen, feeds the ticket's summary and ticked criteria.
- **Agent usage comes from the agent's log or is recorded as not metered** (`createAgentMeter`). Claude Code and Codex are metered; others get one `meter: "not-metered"` row per attempt. Claude Code and Codex use in this repo that shepherd did not start is ledgered by `sweepAgentLogs` (`agent-sweep.ts`, reason "outside chef") at `/cost`, `/review` and `/build` start and by the hooks, from the one per-repo watermark `<workspace>/agent-logs.json` (`{ since, files: { path: { offset } } }`). Read-modify-write of it (sweep, `advanceAgentLog`) holds `store.withWatermarkLock`, because hooks of several sessions run at once. The ticket and agent-review meters advance it for what they ledger so nothing counts twice, the repo's first sweep only records where the logs stand, and a live build claim on the active task skips the sweep. A sweep given the session's `transcriptPath`/`sessionId` (the Stop and prompt hooks) labels that file "session" and its `<session>/` subagent logs "session subagent"; rows go to the active task, else `session`/IDLE. `.shepherd/` must be git-ignored in a repo shepherd works in (the watermark and its lock are untracked files).
- **Every model call reaches the ledger.** Session turns come from `message_end`; calls shepherd makes record themselves; Pi's own calls are swept from the session file by `sweepPiUsage` into `recordPiUsage`, once per entry id. A failed call ledgers what the provider reported, else unknown. Only the runners' own ledgering tags rows ` · ticket <id>`; the main session's turns never are.
- **Hooks never throw and exit 0** unless they block by JSON output: any error is one stderr line and no stdout; not a git repo or an invalid config does nothing. `prompt` lets `/` commands through, blocks at a hard budget, warns once per task per day at a soft one (`warned.json`); `pretool` (Bash) denies `git push`, branch changes and `git worktree` during a live build claim, and `shepherd build|review|fix` and `hc run` over budget.
- **The daily budget spans repos:** the CLI registers each workspace dir in `$SHEPHERD_HOME/repos.json` and sets `WorkflowContext.dailyRecords` to today's rows from every registered ledger (read-only); without it `budgetState` reads the repo ledger.
- **Claude Code idle-cache warning (hooks):** Stop writes `sessions/<id>.json` (`lastTurnEnd`, `contextTokens` of the last assistant message, `model`); `prompt` blocks over both thresholds and lets the same prompt (sha256) through within 2 minutes via `sessions/<id>.pending.json`.
- **The Pi idle-cache warning (to be removed with the extension) runs in the `input` hook, before a send.** `budgets.idleWarnMinutes` and `idleWarnTokens` (0 disables); `message_end` stamps the last assistant turn with the workflow clock. Interactive, non-command input with a UI only; it never throws, and the dollar figure is omitted when the model has no `pricing` row.
- **Unknown cost is never zero.** Record `actualUsd: null`; budgets count an estimate from tokens and the dearest price, else `budgets.unknownCallUsd`. The estimate lives in `summarize`, never in a ledger row. Money math is integer micro-USD.
- **Review findings are scored 1-10 for likelihood and severity; risk is the product** (`src/review/risk.ts`). Below `MIN_RISK` (5) or unscored is dropped; never default a score. The per-ticket review gates (`TICKET_FAIL_RISK` 20 fails the ticket) and its lower findings are carried into the first `/review` after it (newer than the last saved report); the `/review` model pass advises and never changes `passed`. A "Fix all in a tab" run never commits (a commit it makes is soft-reset while the branch is unchanged) and never reaches the main session.
- **Checks are command lines, never prose, and run without a shell.** Every check and setup command passes `assertCommandSafe`. `validateTickets` rejects shell syntax and commands not on `PATH`. A check that cannot run (`ran: false`) fails the ticket without counting against the model.
- **Spawn with `execFile` and argv arrays, never a shell.** Put `--` before user-derived refs.
- **Writes to `.shepherd/` go through `atomicWrite`, `withLock`, or append-only files.** Never truncate `events.jsonl` or the ledger.
- **Phase changes go through `transition`** (`machine.ts`). Commands return results through `guard` and do not throw to Pi. A command result is plain text; markdown escapes belong only inside table cells.
- **The active task resolves from the checked-out branch, then from `active-task.json`** (`activeTask` in `tasks.ts`), reacting to branch changes only.
- **Commits:** `GitWorkspace` uses `shepherd <shepherd@localhost>` only for a name or email git lacks, and sets `commit.gpgsign=false`. `commitAll` runs with `core.hooksPath=/dev/null` and `--no-verify`, and excludes `.shepherd` paths and new untracked files under an agent's directory (`.claude/`, `.codex/`, `.cursor/`, `.gemini/`, `.opencode/`, `.grok/`). The ticket child's `tool_call` hook (`ticket-mode.ts`) blocks `git push`, branch switches and worktree changes; the main session has no such hook, so an agent ticket is checked after each turn instead (branch, HEAD). No command of this extension pushes.
- **The chat trail is part of the product.** `ctx.progress` posts one-line events and `ctx.report` posts markdown blocks; keep per-ticket lines, the `/build` table and the `/review` stage lines. Timings come from `ctx.now()`, never `Date.now()`.
- **One status line:** `refreshStatus` draws the `chef` footer from `Workflow.statusLine()` using the stored active task, never git.
- **Price every new model** in the user `pricing`, or session start warns once (`unpricedConfigModels`).
- **Tests use fakes** for transports, clocks, Pi and herdr; never a real network call or a real herdr client. `tests/setup.ts` deletes `HC_TERMINAL_ID` and `HC_SCOPE`; tests that reach `/build` or an agent `/review` inject `fakeHerdrClient`. Shared fixtures go in `tests/helpers.ts`.
