# AGENTS.md

claude-shepherd is a Claude Code plugin for `/shepherd:plan` → `/shepherd:build` → `/shepherd:review`: a model per ticket difficulty, a per-ticket review, and cost tracking. Claude Code is the main session; tickets, reviews and fixes run as herdr sub-agents (`hc run`). There is no Pi extension in the main session: Pi is only the worker for Pi-model and local-model sub-agents (`src/ticket-mode.ts`). It is pi-chef rebuilt as a plugin; the history is in `docs/PLAN.md`. User docs: `README.md` and `docs/` (`commands.md`, `configuration.md`, `providers.md`, `COMPATIBILITY.md`). This file is for agents and people changing the repo.

## Commands

```bash
npm test            # vitest, no network
npm run typecheck   # src and tests
npm run build       # tsc to build/ (gitignored; type output only: the panel CLI and the installer run from dist/)
npm run bundle      # esbuild: src/cli/shepherd.ts to dist/shepherd.mjs, src/cli/shepherd-config-main.ts to dist/shepherd-config.mjs (the herdr panel CLI) and src/ticket-mode.ts to dist/ticket-mode.mjs (the Pi worker: Pi's own @earendil-works/* and typebox external, yaml inlined); all committed and kept fresh (CI runs git diff --exit-code dist/)
claude plugin validate .   # the plugin manifest, hooks and skills
```

Run tests with `TMPDIR=~/.cache/pi-chef-rework-tmp npm test` if the default temp dir is unsuitable. Tests, typecheck and the bundle must be green before a change is done. There is no lint script. Keep `docs/` in step with `src/config.ts` (`KNOWN_KEYS`, defaults) and `templates/shepherd.yaml`. `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai` are devDependencies only: `src/ticket-mode.ts` imports types and a helper from the first, and the ticket-mode tests run a real Pi session on the second's faux provider.

## Layout

Entry and shared
- `src/index.ts`: package exports.
- `src/config.ts`: YAML loading, validation, whole-section layering (`layerConfigs`), pricing lookup, `unknownKeys`.
- `src/agents.ts`: built-in external agents, `parseTicketModel`, `agentCommand`. A model after the first `/` of `agent:<name>/<model>` is one argv element, brackets and `=` included (`auto-smart[optimize_for=balanced]`).
- `src/domain.ts`: shared types (task state, phases, tickets, cost records) and `WorkflowError`.
- `src/redact.ts`: secret detection and redaction.
- `src/sandbox.ts`: command walker behind the deny rules (`assertCommandSafe`, `isDeniedCommand`, `ticketBashProblem`) and `buildBashBlock`.
- `src/usage-message.ts`: turns a Pi assistant message into a ledger entry (used by `herdr/session-file.ts` for a Pi child's session).
- `src/ticket-mode.ts`: the one extension a Pi child loads with `-e` (turn budget, bash rules, `local` provider, status file); never listed in `package.json`. It imports only config, `providers/runtime.ts`, `sandbox.ts`, `redact.ts` and `orchestrator/turn-budget.ts`.
- `src/shepherd-home.ts`: `$SHEPHERD_HOME` (default `~/.claude/shepherd`): `repos.json`, `sessions/`, `warned.json`, `cursor-models.json`.

Orchestrator (`src/orchestrator/`)
- `service.ts`: the `Workflow` facade over a shared `WorkflowContext` (`context.ts`). `types.ts`: `WorkflowOptions`. There is no `bind`, chat client, registry, `startTurn`, `review` or `edit` hook: a Workflow is made once per command, with `progress`, `report`, `confirm`, `herdr` and the test seams.
- `machine.ts`: phase transitions. `format.ts`: progress and report formatting.
- `planning.ts`: new tasks, approval, showing a plan. `interview.ts`: `startPlan`, `savePlanSpec` (the planner's rating), `requestPlanChanges`, `interview.json` (`{version, request}`). `prompts.ts`: the planning rules `shepherd plan` prints and the ticket prompt. `plan.ts`: `plan.md`. `classification.ts`: the planner's rating.
- `tickets.ts`, `ticket-plan.ts`: ticket validation, context sizing, ticket files.
- `tasks.ts`: names, listing, active task, closing (clears the build marker). `plans.ts`: `/shepherd:plans`.
- `build.ts`: `startBuild`, `nextChunk`, `finishChunk`, `runBuild`, pure over a `BuildDriver`. `routing.ts`: model per difficulty and escalation. `turn-budget.ts`: ticket turn limit. `ticket-review.ts`: the per-ticket review gate and its parser; `ticket-review-tab.ts` runs it in a herdr sub-agent.
- `review.ts`: `/shepherd:review`. `review-report.ts`: its report and numbered findings. `agent-review.ts`: the model pass run in a herdr sub-agent, by an external agent or a Pi child (`runAgentReview`; one turn, no chunking: the reviewer runs `git diff <merge-base>` itself). `tab-program.ts`: the Pi-child and agent programs (argv, ledgering, reply) shared by the fix and the ticket review. `review-fix.ts`: "Fix all in a tab", the findings fixed by `models.medium` in a sub-agent, ledgered as "review fix". `review-latest.ts`: the latest saved report, `fixModel`, the fix on it.
- `budget.ts`: usage recording and budget checks. `reports.ts`: `/shepherd:cost`. `exec.ts`: running checks. `agent-sweep.ts`: the outside-chef sweep.

Runners, providers, review, storage
- `src/cli/build-host.ts`: the `/build` driver (`createBuildDriver`: herdr preflight, `pi`-on-PATH check, `runTicket`) and `ticketModePath()` (walks up from the module: `dist/shepherd.mjs`, `build/cli/`, `src/cli/`; prefers `<plugin>/dist/ticket-mode.mjs`, which a plugin install can load without node_modules, else `src/ticket-mode.ts`). `src/cli/build.ts`: `shepherd build [--once] [--json]` over `runBuild` (progress to stdout; with `--json` stdout is one `{ok, code?, text, data}` document; `data` for `--once` is `{ticket?, outcome: committed|stopped|done, done, stopped?, next?, report?}`; SIGINT/SIGTERM kill the open tabs, release the claim, clear the marker and exit 130). Test seams in `CliOptions`: `herdr`, `runner`, `herdrTimings`, `piAvailable`, `ticketModePath`, `exit`. Skill: `skills/build`.
- `src/cli/review.ts`: `shepherd review [--with <model>] [--json]` and `shepherd fix --tab|--list [--json]`. No `report` listener is bound, so a review's result text is the whole numbered report. `--json` gives `{ok, code?, text, data}`; a review's `data` is `{report, findings: [{n, title, file, line (always null), risk}], passed, fixTab}`; a blocking review is `ok: false, REVIEW_BLOCKING`, exit 1. Skill: `skills/review`.
- `src/runner/ticket.ts`: dispatch (Pi model or agent) and the herdr requirement. `tab.ts`: the one open/send/wait/close loop (tab names, `send --wait`, blocked handling). `pi-ticket.ts` and `agent-ticket.ts`: how each starts its program and what it collects after a turn (a Pi child's session files; an agent's usage log, branch check and summary file). `host.ts`: session dirs, ledgering, git moves. `agent-usage.ts`: metering from agent logs. `pi-path.ts`: `pi` on PATH.
- `src/herdr/client.ts`: typed wrapper over `hc` (self, run, send, waitIdle, read, kill). `session-file.ts`: reads a Pi child's session files for usage.
- `src/providers/`: `runtime.ts` (registers `local`, in the Pi child), `known-models.ts` (presets), `local-context.ts` (served context probe, used by the panel).
- `src/review/`: `review.ts` (checks and static scan), `model-review.ts` (the lenient reader of a model's findings list: `parseModelFindings`), `risk.ts` (scoring shared by all reviews), `scored-json.ts` (reading, deduping and filtering scored findings, shared by the model pass, agent review and ticket review).
- `src/cost/ledger.ts`: summaries and budget status. `src/storage/store.ts`: task state, event log, ledger, ticket log, locks, the build claim and the build-in-progress marker. `src/git/workspace.ts`: git over `execFile`.
- `src/cli/shepherd.ts` (the `shepherd` CLI, run through `bin/shepherd`; bundled to `dist/shepherd.mjs`): `cost [--json]`, `status`, `migrate-config`, and `hook stop|prompt|pretool` (the plugin's hooks, `hooks/hooks.json`). `src/cli/bash-guard.ts`: the command splitter behind the PreToolUse guard. `src/cli/migrate-config.ts`: `shepherd migrate-config`.
- `src/cli/plan.ts`: `shepherd plan start|spec|tickets|show|revise|approve`, `plans` and `task list|use|close`, thin adapters over the `Workflow` planning methods (all take `--json`: `{ok, code?, text, data?}`; file args are a path or `-` for stdin; exit 1 on a failed result). Claude Code drafts and the CLI validates; there is no interview in code (it lives in `skills/plan`, its answers go into the spec's `decisions`). `cliText` rewrites the orchestrator's `plan_spec`/`/plan`/`/build` wording into the CLI's. `pretool` returns `ask` for `shepherd plan approve` (reason names task, tickets, models), so the approval is the user's whatever a skill's `allowed-tools` say. Skills: `skills/plan`, `skills/plans`.
- Plugin: `.claude-plugin/plugin.json` and `marketplace.json` (the plugin name must not start with `claude-`), `hooks/hooks.json`, `skills/<name>/SKILL.md`. Check with `claude plugin validate .` (it needs `README.md`; the missing icon is a warning).
- `src/cli/shepherd-config.ts` (with `bin/shepherd-config.mjs`): JSON CLI for the herdr panel (`show`, `set`, `local-*`, `cursor-models`, `plan-*`). `src/cli/herdr-layout.ts`: docks the panel in a layout (id and layout `shepherd`, mod `shepherd-config`).

Elsewhere: `src/cli/herdr-install.ts` (`shepherd herdr-install`, logic bundled into dist/shepherd.mjs; `scripts/herdr-install.mjs` and `bin/shepherd-config.mjs` are shims over the bundles; `src/cli/shepherd-config-main.ts` is the entry of dist/shepherd-config.mjs; the installer copies the mod and that bundle into the herdr app's mods folder and writes install.json inside it, never into the plugin folder; honours `$HERDR_APP_HOME`; test it against a scratch dir, never your real herdr app home), `herdr/shepherd-config/` (the panel mod; check with `node --check` and `herdr-app check herdr/shepherd-config`), `templates/shepherd.yaml` (user config template), `templates/project-config.yaml` (project sample; two tests read it), `tests/` (mocks only; `helpers.ts`, `herdr-fake.ts`).

## Rules

- **Pi is a worker, not a host.** Nothing in `src/` except `ticket-mode.ts` and `providers/runtime.ts` loads Pi. shepherd never reads provider key variables and never calls a model itself: every model call is a herdr sub-agent (an agent CLI or a `pi` child) whose usage is read back from its own log or session files. Prices come from `pricing` rows; a model with no row is an unknown cost, never $0 (except `local`). Do not name a config field so it ends in a secret word (`apiKey`, `token`): `containsSecret` rejects it.
- **No secrets in config or state.** `assertNoSecrets` enforces it. The local server's key is a variable name (`local.apiKeyEnv`) that Pi resolves. Never log secrets or write them to state, the ledger or prompts.
- **Policy is deterministic; models only fill validated schemas.** Plan approval is always required. Nothing pushes, opens a PR or merges.
- **Layering is one rule:** a project section replaces the user's whole section (`layerConfigs`). `local`, `agents`, `pricing` and `workspaceDir` are user-only; a project value is ignored with a warning. Remote `local.baseUrl` must be https; only loopback may be http. An agent's `run` comes from the user file only.
- **Unknown config keys are ignored with one warning** (`KNOWN_KEYS` in `config.ts`); the CLI does not print it, the panel and `migrate-config` do. `review.maxDiffChars` and `maxChunks` are such keys now. Any invalid value, secret or bad YAML rejects the whole file (`ConfigFileError`); a command reports it and never crashes.
- **Routing:** a ticket starts on `models.<difficulty>` (`modelFor`), climbs low, medium, high on failure (a rung naming the same model is skipped) and stops above `high`. `routing.maxEscalations` counts rungs climbed to the next rung with another model. Resume keeps the rung (`TicketRun.tier`); review rounds are counted per rung.
- **Every `/build` ticket runs in its own herdr sub-agent (or tab with `build.visibleTabs`), in the current checkout.** Without herdr, `runBuild` returns `NEEDS_HERDR` before `startBuild`, so no branch is made. The driver never throws; `runTicket` returns `{ stopped }`. A fresh build gets `<branchPrefix>/<name>` from the default branch; `startBuild` claims the task by pid.
- **Sub-agents are paneless by default.** `hc run` from inside the Claude Code terminal records it as the child's `parent`; ticket, review and fix runs pass no `herdr.space`/`herdr.tab` label (`openTab` adds them only when given a `space`, which `herdrSpace(client, visible)` yields only with `build.visibleTabs: true`). The preflight needs only `HC_TERMINAL_ID` and a working `hc`. Each run keeps a `shepherd.*` label.
- **The per-ticket review runs in a sub-agent.** `reviewTicket` uses `askInTab`: `models.review` as an agent or a Pi child, which reads the checkout (`git diff HEAD`) and writes `{summary, findings}` JSON to `reports/ticket-review-<id>-<time>.json`. Same parser, risk filter and `TICKET_FAIL_RISK` gate. Rows are `ticket review · ticket <id>`, tier `review`. HEAD and branch are guarded (a commit is soft-reset, a branch change is unavailable) and the diff is fingerprinted: a review that edited the tree is unavailable, so the ticket is committed with a warning. There is no retry of an unreadable answer. Skipped when `review.tickets` is false or no herdr client is bound. A Pi review's session dir is `sessions/review-<ticket>-<time>`, never `<ticket>-<n>`.
- **The /review model pass always runs in a herdr sub-agent** (`modelPass` → `runAgentReview`: an agent or a Pi model). Rows are `model review`, tier `review`, phase REVIEWING, under the task (else `session`); a Pi child's rows take that task and phase through `piProgram`/`ledgerChildSession`. Without herdr the setup, checks and static scan still run and the model stage reads "the model pass needs herdr". `shepherd fix --tab` fixes the latest report's findings on `models.medium` in a sub-agent (`review fix`, never commits).
- **There is no Pi registry.** Routing (`routeFor`) blocks a Pi model when `ctx.piAvailable` says `pi` is not on PATH; `shepherd build` fails `NEEDS_PI` first when the next ticket starts on one. Whether Pi knows the model or has a login is the Pi child's to say.
- **`shepherd build --once` builds one ticket** (`runBuild(..., {once: true})`: exits after the first commit; stops and escalation are unchanged) and holds the build claim only while it runs.
- **The build-in-progress marker** (`<task dir>/build.active`, `store.markBuilding` / `clearBuilding` / `buildInProgress`) is set by `startBuild` and kept between `--once` runs. `runBuild` clears it only when a run that started ends the build: a ticket stops it, the last ticket is built (`data.done`), or a full build ends; a signal clears it; `closeTask` clears it. A run that never started (`NEEDS_HERDR`, `BUILD_RUNNING`, a refused start such as `DIRTY_TREE` or `BUDGET`) leaves it. The pretool guard denies `git push`, branch changes and `git worktree` while the marker is set or a live claim exists (and the task is open). The way out of a stale marker is a build that ends, or `shepherd task close <name> --force`.
- **A Pi ticket child is a `pi` of its own** (`pi -ne -e ticket-mode.ts --model … --session-dir …`, environment through an `env` wrapper); its session files are ledgered (`ledgerChildSession` → `observeUsage`, `recordPiUsage`; both stay because of this). **An agent ticket is a CLI in a sub-agent and shepherd owns the commit:** a commit the agent makes anyway is undone with `git reset --soft`, but only while the checkout is still on the build branch (else the ticket stops and HEAD is left alone). The agent writes its summary and criteria checklist to a file under the task's `sessions/`; that file, not the screen, feeds the ticket's summary and ticked criteria.
- **Agent usage comes from the agent's log or is recorded as not metered** (`createAgentMeter`). Claude Code and Codex are metered; others, Cursor included, get one `meter: "not-metered"` row per attempt ($0). Claude Code and Codex use in this repo that shepherd did not start is ledgered by `sweepAgentLogs` (`agent-sweep.ts`, reason "outside chef") at `/cost`, `/review` and `/build` start and by the hooks, from the one per-repo watermark `<workspace>/agent-logs.json` (`{ since, files: { path: { offset } } }`). Read-modify-write of it (sweep, `advanceAgentLog`) holds `store.withWatermarkLock`, because hooks of several sessions run at once. The ticket and agent-review meters advance it for what they ledger so nothing counts twice, the repo's first sweep only records where the logs stand, and a live build claim on the active task skips the sweep. A sweep given the session's `transcriptPath`/`sessionId` (the Stop and prompt hooks) labels that file "session" and its `<session>/` subagent logs "session subagent"; rows go to the active task, else `session`/IDLE. `.shepherd/` must be git-ignored in a repo shepherd works in (the CLI writes `.shepherd/.gitignore`).
- **Every model call reaches the ledger.** The main session's turns come from the `Stop` hook; calls shepherd starts record themselves; a Pi child's own calls are read from its session files once per entry id (`recordPiUsage`). A failed call ledgers what the provider reported, else unknown. Only the runners' own ledgering tags rows ` · ticket <id>`; the main session's turns never are.
- **Hooks never throw and exit 0** unless they block by JSON output: any error is one stderr line and no stdout; not a git repo or an invalid config does nothing. `prompt` lets `/` commands through, blocks at a hard budget, warns once per task per day at a soft one (`warned.json`); `pretool` (Bash) denies `git push`, branch changes and `git worktree` during a build (marker or live claim), denies `shepherd build|review|fix` and `hc run` over budget, and asks for `shepherd plan approve`.
- **The daily budget spans repos:** the CLI registers each workspace dir in `$SHEPHERD_HOME/repos.json` and sets `WorkflowContext.dailyRecords` to today's rows from every registered ledger (read-only); without it `budgetState` reads the repo ledger.
- **The idle-cache warning (hooks):** Stop writes `sessions/<id>.json` (`lastTurnEnd`, `contextTokens` of the last assistant message, `model`); `prompt` blocks over both thresholds (`budgets.idleWarnMinutes`, `idleWarnTokens`; 0 disables) and lets the same prompt (sha256) through within 2 minutes via `sessions/<id>.pending.json`. The dollar figure is omitted when the model has no `pricing` row.
- **Unknown cost is never zero.** Record `actualUsd: null`; budgets count an estimate from tokens and the dearest price, else `budgets.unknownCallUsd`. The estimate lives in `summarize`, never in a ledger row. Money math is integer micro-USD.
- **Review findings are scored 1-10 for likelihood and severity; risk is the product** (`src/review/risk.ts`). Below `MIN_RISK` (5) or unscored is dropped; never default a score. The per-ticket review gates (`TICKET_FAIL_RISK` 20 fails the ticket) and its lower findings are carried into the first `/review` after it (newer than the last saved report); the `/review` model pass advises and never changes `passed`. A "Fix all in a tab" run never commits (a commit it makes is soft-reset while the branch is unchanged) and never reaches the main session.
- **Checks are command lines, never prose, and run without a shell.** Every check and setup command passes `assertCommandSafe`. `validateTickets` rejects shell syntax and commands not on `PATH`. A check that cannot run (`ran: false`) fails the ticket without counting against the model.
- **Spawn with `execFile` and argv arrays, never a shell.** Put `--` before user-derived refs. An agent's argv is built by `agentCommand`; a model with brackets stays one element.
- **Writes to `.shepherd/` go through `atomicWrite`, `withLock`, or append-only files.** Never truncate `events.jsonl` or the ledger.
- **Phase changes go through `transition`** (`machine.ts`). Commands return results through `guard` and do not throw. A command result is plain text; markdown escapes belong only inside table cells.
- **The active task resolves from the checked-out branch, then from `active-task.json`** (`activeTask` in `tasks.ts`), reacting to branch changes only.
- **Commits:** `GitWorkspace` uses `shepherd <shepherd@localhost>` only for a name or email git lacks, and sets `commit.gpgsign=false`. `commitAll` runs with `core.hooksPath=/dev/null` and `--no-verify`, and excludes `.shepherd` paths and new untracked files under an agent's directory (`.claude/`, `.codex/`, `.cursor/`, `.gemini/`, `.opencode/`, `.grok/`). The ticket child's `tool_call` hook (`ticket-mode.ts`) blocks `git push`, branch switches and worktree changes; Claude Code's own Bash has the pretool guard, and an agent ticket is checked after each turn (branch, HEAD). No command of this plugin pushes.
- **The result trail is part of the product.** `ctx.progress` posts one-line events and `ctx.report` posts markdown blocks; keep per-ticket lines, the build table and the review stage lines. Timings come from `ctx.now()`, never `Date.now()`.
- **`shepherd migrate-config`** never overwrites (`--force` writes `shepherd.yaml.bak`, `.bak.2`, … first), drops keys `unknownKeys` names with the YAML Document API (comments stay), and writes nothing unless `parseConfig` accepts the result.
- **The panel's model picker** offers `agent:cursor-agent/auto`, and the three `auto-smart[optimize_for=...]` settings only when `cursor-agent --list-models` lists `auto-smart` (`cursorModels`: 4 s timeout, cached an hour in `$SHEPHERD_HOME/cursor-models.json`). Cursor is not metered, and the router needs a Teams or Enterprise plan.
- **Tests use fakes** for transports, clocks, Pi and herdr; never a real network call or a real herdr client. `tests/setup.ts` deletes `HC_TERMINAL_ID` and `HC_SCOPE` and points `HOME` at an empty directory; tests that reach `/build` or an agent `/review` inject `fakeHerdrClient`. Shared fixtures go in `tests/helpers.ts`.

## Unverified against live services

The `/build` loop with a Pi model, Codex and Cursor, the idle warning and the pretool denies in a live session, and the panel in a live herdr app have only run against fakes. The full list is in `docs/COMPATIBILITY.md#unverified-live`.
